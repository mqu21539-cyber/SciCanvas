### 2.3 产物质量抽检（Doppler）

模型实际写出的东西：

- **物理**：`λ前 = (c − v)/f`、`λ后 = (c + v)/f`、`sin(α) = c/v`，超音速才画马赫锥——公式正确，不是套壳动画。

- **教学**：自动生成了一句"直觉挑战"（把速度调到 0，波前会变成什么形状）。

## 五、分模块可行性

### 5.1 双 Agent 生成 — ✅ 高（已实测）

三次生成、零失败、零语法错误，产物可直接在浏览器运行。**核心假设成立。**

**剩余风险 = 物理正确性**：Doppler 这次对，不代表引力弹弓那次也对。三次里我只逐行核了 Doppler 的物理，另外两个只做了结构校验。

**建议**：把 4 个展厅实验变成**回归基准**——每次改 prompt 后重跑，人工核对公式是否仍正确。

### 5.2 dsh 插件 — ⚠️ 唯一未验证项

**已验证**：`tsc` 编译通过、`name/apply` 导出正确、双模降级逻辑完整。
**未验证**：`ctx.tool.register` / `ctx.agent.registerTool` 是否真的存在于 dsh 运行时。

已改为**找不到入口就抛错**：`装上了但没有工具` 是最难排查的失败模式，不如当场炸。

**建议**：0.5 天做探针（`apply(ctx){ console.log(Object.keys(ctx)) }`），拿到真实 API 再改。

### 5.3 展厅 / BYOK — 🟡 中

- 预生成展厅：**零风险**，纯静态，4 个实验已验证可加载。
- BYOK 浏览器直连：**仍有 CORS 风险**。已加醒目前提说明 + 失败原因引导；正式 Demo 不依赖它。

### 5.4 自愈闭环 — 🟡 未压测

三次生成**都没有触发 JS 报错**，所以 `/api/fix` 这条链路这次完全没被走到。这是好消息，也是覆盖缺口：**自愈的收敛率仍然未知**。

**建议**：人为注入一个错误（删掉一个变量声明）做一次定向测试，确认闭环真的能修好。

### 5.5 CI / 发布 — 🟡

workflow 语法已修；`configure-pages@v5` + `upload-pages-artifact@v3` + `deploy-pages@v4` 是官方推荐组合。端到端验证要等推到 GitHub。

## 六、性能与成本（实测）

### 6.1 吞吐与耗时

由第一次运行反推：Coder 输出 6,941 tokens / 23.8 s ≈ **291 tok/s**。

| 阶段 | 实测耗时 | token |
| :--- | :--- | :--- |
| Planner | 3.1–3.4 s | ~490 入 / ~510 出 |
| Coder | 21.7–26.9 s | ~910 入 / ~6,900 出 |
| **合计** | **24.8–30.0 s** | **~1,400 入 / ~7,450 出** |

**"10 秒"怎么办**：实测是 25–30 秒。建议口径统一成 **"10 秒出科学蓝图，约 30 秒出可玩沙盒"**——数字诚实，且 30 秒这个量级用户完全能接受（比等一个 DALL·E 出图久一点而已）。

> 如果一定要"10 秒内"，只剩 Coder 输出瘦身一条路：把 700 行砍到 250 行以内，或改模板化生成（见 §8）。**但 30 秒已经不构成产品缺陷，我建议不做。**

### 6.2 成本

| 场景 | 输入 tokens | 输出 tokens |
| :--- | :--- | :--- |
| 单次生成（实测） | ~1,400 | ~7,450 |
| 触发 1 次自愈 | +约 8,000 | +约 7,000 |

按 DeepSeek 官方价目表换算（本文未核价，发布前请自行核对）。三个降本抓手，按性价比排序：

1. **本地缓存**：同一 prompt 二次点击直接读缓存，零成本；
2. **上下文缓存**：两个 system prompt 是固定前缀，命中缓存可省输入侧；
3. **自愈瘦身**：别回传整份 HTML，只回传出错函数 + 行号。

## 十、B 方案实测（原型已落地）

`B-模板化生成/` 不是空目录：`generator.py` + 2 个手写参数化模板（阻尼单摆、抛体运动）已可运行。

| 指标 | A · 自由生成 | B · 模板化 |
| :--- | :--- | :--- |
| 模型输出 tokens | ~6,900 | **96** |
| 模型输入 tokens | ~1,400 | **405** |
| 端到端耗时 | 24.8–30.0 s | **3.8 s** |
| 产物 | 500–700 行 HTML | ~250 行（模板复用） |
| 可测试性 | 需抽检物理 | 模板可写单元断言 |

**为什么 B 快**：它把"写代码"这个最大的 token 消耗项整个删掉了——模型只输出 `{"template":"projectile","params":{"k":0.3},"title":…}` 这种量级的东西。

**B 的真实短板**：模板库没有的概念只能"选最接近的 + 标注近似"。所以 B 不是 A 的替代，而是 A 的快车道。

**建议的 v0.2 架构（混合路由）**：

```
用户输入 → 问模型"属于哪个模板？"
              ├─ 命中 → B 渲染（≈4 s，物理必然正确）
              └─ 未命中 → 回落 A 双 Agent（≈30 s，任意概念）
```

这样常见概念走 4 秒快路径，长尾仍有兜底。实现上只多一个路由函数，`plan_from_text` 已经能判断是否命中注册表。

**B 的剩余工作**：模板从 2 个扩到 6 类（波动/场/轨道/优化/概率/网络）约 1 d；接进 A 的前端做混合路由约 0.5 d。
