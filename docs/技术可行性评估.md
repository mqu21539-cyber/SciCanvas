## 六、性能与成本（实测）

### 6.1 吞吐与耗时

由第一次运行反推：Coder 输出 6,941 tokens / 23.8 s ≈ **291 tok/s**。

| 阶段 | 实测耗时 | token |
| :--- | :--- | :--- |
| Planner | 3.1–3.4 s | ~490 入 / ~510 出 |
| Coder | 21.7–26.9 s | ~910 入 / ~6,900 出 |
| **合计** | **24.8–30.0 s** | **~1,400 入 / ~7,450 出** |

**"10 秒"怎么办**：实测是 25–30 秒。建议口径统一成 **"10 秒出科学蓝图，约 30 秒出可玩沙盒"**——数字诚实，且 30 秒这个量级用户完全能接受（比等一个 DALL·E 出图久一点而已）。

> 如果一定要"10 秒内"，只剩 Coder 输出瘦身一条路：把 700 行砍到 250 行以内，或改模板化生成（见 §8）。**但 30 秒已经不构成产品缺陷，我建议不做。**

### 6.1.1 模板快车道（v0.4 起）

同一句"演示单摆的阻尼振动"，走模板只要 **1.4–1.6 s**——分诊 1.0 s + 本地渲染 0.4 s，
token 消耗约 405 入 / 96 出。10 个模板覆盖的概念都落在这个量级，所以上面的"10 秒"承诺
对这部分概念是成立的；只有没命中模板的长尾才走 25–30 秒的双 Agent。

### 6.1.2 arXiv 摘要直读（v0.8 新增）

输入 `arXiv:1706.03762` 或 `https://arxiv.org/abs/...`，后端调用 arXiv 官方 API 取
标题与摘要（实测 **0.6 s**），再拼成提示词交给流水线。端到端实测：**29.1 s**、
产物 20,626 字符、`mode=agent`、返回体带 `arxiv{id,title,url}` 供前端展示出处。

- 抓取失败或离线时**自动回落**到用户原文，不阻断生成
- 缓存键用展开后的「标题+摘要」，换论文即换键，不会串味

### 6.1.3 全息 2.5D 改造后（v0.12–0.13）

按《全息 2.5D 交互升级方案》路线 C 重构：底座承担四层 SVG 舞台与全部交互，
模型/模板只写物理逻辑。

| 指标 | 改造前 | 改造后 |
| :--- | :--- | :--- |
| 双 Agent 路径端到端 | 25–30 s | **17.2 s** |
| Coder 产出 | 600–700 行完整 HTML | ~50 行 `reset/frame` |
| 模板帧率 | 60 FPS（canvas） | **60 FPS（10/10 个模板，SVG 四层）** |
| 产物结构 | 单个 canvas | L0/L1/L2/L3 可拆解，可残影、可靶向 |

关键取舍：

1. **不用 Sandpack**。原方案基于 Sandpack，我们继续用 `iframe sandbox="allow-scripts"`
   —— 更轻、已经过 10 个用例验证，`postMessage` 协议照样能跑。
2. **残影用"冻结画面快照"而不是"跑第二套并行仿真"**。文档版本要求每个实验维护双份状态机；
   改成冻结当前 L1/L2 的 SVG 快照并染色品红，对任意实验通用，代价是残影不会跟着新参数演化。
3. **片段校验必须有回落**。实测模型仍会时不时写整份 HTML，所以 `holo_build.py` 做了
   6 类结构校验，不合格立刻回落老的整份生成——宁可慢，不能出不来东西。

### 6.2 成本

| 场景 | 输入 tokens | 输出 tokens |
| :--- | :--- | :--- |
| 单次生成（实测） | ~1,400 | ~7,450 |
| 触发 1 次自愈 | +约 8,000 | +约 7,000 |

按 DeepSeek 官方价目表换算（本文未核价，发布前请自行核对）。三个降本抓手，按性价比排序：

1. **本地缓存**：同一 prompt 二次点击直接读缓存，零成本；
2. **上下文缓存**：两个 system prompt 是固定前缀，命中缓存可省输入侧；
3. **自愈瘦身**：别回传整份 HTML，只回传出错函数 + 行号。

## 十、模板路径实测（原型已落地）

`backend/` 不是空目录：`generator.py` + 2 个手写参数化模板（阻尼单摆、抛体运动）已可运行。

| 指标 | 双 Agent | 模板 |
| :--- | :--- | :--- |
| 模型输出 tokens | ~6,900 | **96** |
| 模型输入 tokens | ~1,400 | **405** |
| 端到端耗时 | 24.8–30.0 s | **3.8 s** |
| 产物 | 500–700 行 HTML | ~250 行（模板复用） |
| 可测试性 | 需抽检物理 | 模板可写单元断言 |

**为什么 B 快**：它把"写代码"这个最大的 token 消耗项整个删掉了——模型只输出 `{"template":"projectile","params":{"k":0.3},"title":…}` 这种量级的东西。

**B 的真实短板**：模板库没有的概念只能"选最接近的 + 标注近似"。所以 B 不是 A 的替代，而是 A 的快车道。

**建议的 v0.2 架构（混合路由）**：

```
用户输入 → 问模型"属于哪个模板？"
              ├─ 命中 → B 渲染（≈4 s，物理必然正确）
              └─ 未命中 → 回落 A 双 Agent（≈30 s，任意概念）
```

这样常见概念走 4 秒快路径，长尾仍有兜底。实现上只多一个路由函数，`plan_from_text` 已经能判断是否命中注册表。

**B 的剩余工作**：模板从 2 个扩到 6 类（波动/场/轨道/优化/概率/网络）约 1 d；接进 A 的前端做混合路由约 0.5 d。
