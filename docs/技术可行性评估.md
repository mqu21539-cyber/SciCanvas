| 前端交互沙盒 | ✅ 可行 | `next build` 通过（含 TypeScript strict 类型检查） |
| dsh 插件 | ⚠️ 半可行 | 能编译出 `lib/index.js`，但**工具注册 API 未经验证，是教程作者的猜测** |

| "10 秒出实验室" | ❌ 大概率不成立 | 按 token 量估算实际 **90–170 秒**，需改口径或改架构 |

**三个前置问题（按优先级）**

1. **dsh 插件注册入口是猜的**——`ctx.tool?.register()` / `ctx.agent?.registerTool()` 两条路径都不存在时，代码会静默跳过，插件"装了但没工具"。这是教程里技术含金量最高、也最不确定的一段。
2. **"10 秒"是产品承诺级谎言**——用户会拿秒表验证。要么改文案，要么改架构（模板化生成）。
3. **BYOK 浏览器直连 DeepSeek**——第三方 API 未必返回 CORS 头，且把 Key 放 localStorage 是安全权衡。

## 五、分模块可行性

### 5.1 双 Agent 生成流水线 — ✅ 高

**成立的原因**：单文件 HTML 是"零集成成本"的产物形态，不需要构建、不需要依赖树、天然适合 iframe `srcdoc` 渲染；Planner 用 `response_format=json_object` 把"科学概念"约束成有限字段，避免了自由文本的不可控。

**风险**：模型产出的物理正确性无法保证（Planner 可能编造公式、Coder 可能把阻尼系数写成 `damping * 2` 之类的凭空常数）。**这是产品级风险，不是工程风险**——沙盒能跑不代表物理对。

**建议**：给 3 个预设案例写死"黄金实现"，作为回归基准；每条生成结果里展示 `formula_latex`，让用户能一眼质疑公式。

### 5.2 dsh 插件 — ⚠️ 中（最大不确定点）

**已验证**：能编译、`name/apply` 导出正确、双模降级逻辑（探活→直连）代码完整。

**未验证**：
- `ctx.tool?.register(spec)` 与 `ctx.agent?.registerTool(spec)` —— 这两个入口名**没有任何证据**存在于 dsh 运行时的 Cordis Context 上。代码用了 `?.` 防御，后果是**两条都不命中时静默不注册**，插件加载"成功"但没有任何工具。
- 工具 spec 的字段约定（`name/description/parameters/execute`）是否等于 dsh 的 Tool 定义。
- `cordis.yml` 的 `plugins:` 段是否真被 dsh 读取、`${DEEPSEEK_API_KEY}` 是否支持环境变量插值。

**建议**：先花 0.5 天做**验证探针**——写一个 10 行的插件，在 `apply` 里 `console.log(Object.keys(ctx))`，把它挂进 dsh 看实际 Context 上有哪些可注册面。拿到真实 API 再改 `index.ts`，改完才谈 `npm publish`。

### 5.3 静态展厅 + BYOK — 🟡 中

- 展厅部分（manifest 切换 + iframe 预览 + 下载）**零风险**，纯静态、无依赖。
- **BYOK 有真实阻碍**：浏览器直接 `fetch("https://api.deepseek.com/chat/completions")` 需要对方返回 `Access-Control-Allow-Origin`。多数大模型 API 默认不放行浏览器来源（防 Key 泄露）。若不通过，这个"零后端试玩"就是死的。
- 附带问题：Key 存 `localStorage`，同源 XSS 可读；页面还引了 `cdn.tailwindcss.com` 这个第三方脚本——**把 Key 和不可信 CDN 放在同一页是明确的供应链风险**。

**建议**：BYOK 改为"可选实验特性"并明确提示；正式 Demo 走 `gallery/labs/` 预生成产物（这条路 100% 可靠）。真要在浏览器直连，自建一层同源代理（Cloudflare Worker 20 行）更干净。

### 5.4 前端沙盒与自愈闭环 — ✅ 高（但有收敛风险）

`iframe sandbox="allow-scripts"` + `postMessage` 回传 + `/api/fix` 重渲染，机制本身成立，且 `allow-scripts` 不含 `allow-same-origin`，沙盒内拿不到父页面 DOM/存储，安全性合格。

**风险**：自愈是"LLM 修 LLM 的错"，不保证收敛。已加 2 次上限止损；但更根本的是**降低出错率**——把 Coder 的约束写得更硬（禁用 `import`、禁用 `async` 顶层、要求所有变量在函数内声明）。

### 5.5 CI / 发布 — 🟡 中

workflow 现在语法合法，`configure-pages@v5` + `upload-pages-artifact@v3` + `deploy-pages@v4` 是当前官方推荐组合。端到端验证必须等仓库推到 GitHub 后才能做（本地无法模拟 Pages 环境）。

## 六、性能与成本（估算，需实测校准）

### 6.1 为什么"10 秒"不成立

按一份多普勒实验的产物量反推（该实验 168 行 / 7.4 KB，属于中复杂度）：

| 阶段 | 输出量估算 | 耗时估算（40–70 tok/s） |
| :--- | :--- | :--- |
| Planner（JSON 蓝图） | 400–800 tokens | 8–20 s |
| Coder（单文件 HTML，300–600 行） | 4,000–8,000 tokens | 60–150 s |
| 合计（不含自愈） | — | **≈ 70–170 s** |
| 若触发 1 次自愈 | 再 +4,000–8,000 tokens | 再 +60–150 s |

对话补全类模型是**串行流式输出**，"生成 500 行代码"在物理上就受 token 速率限制，换更快的模型只能压到 40–80 s。**10 秒内出完整交互实验室，在不改架构的情况下不可能。**

**两条出路**

1. **改文案**（零成本）："10 秒出科学蓝图，90 秒出可玩沙盒"——宣传诚实，且中间态可展示。
2. **改架构**（1–2 天）：老师傅做法是**模板 + 参数填充**。预置 6 类仿真骨架（波动/场/轨道/优化/概率/网络），让模型只输出"用哪个模板 + 参数 + 文案"（≈1,200 tokens），前端把参数填进模板。这样 **15–25 秒可达**，且产物质量稳定、可控、不跑偏。代价是自由度下降。

> 建议：MVP 先走"改文案"，把架构 2 当作冲量后的重构。README 里的 "in 10 seconds" 建议同步改掉，否则第一个 Hacker News 评论就会抓着这个打。

### 6.2 单次生成成本

| 项 | tokens |
| :--- | :--- |
| 首轮输入（system×2 + 蓝图） | ≈ 2,000 |
| 首轮输出 | ≈ 5,000–8,500 |
| 自愈一轮 | ≈ +10,000（输入含原 HTML） |
| 单次生成典型总量 | **≈ 7k 入 / 6k 出** |

按 DeepSeek 当前官方价目表换算（本次未核价，请在发布前自行核对）。成本优化的两个抓手：
- Planner 与 Coder 的 system prompt 是**固定前缀**，命中 context cache 可显著降本；
- 自愈把整份 HTML 回传成本最高，可改为**只回传出错函数 + 行号上下文**。
